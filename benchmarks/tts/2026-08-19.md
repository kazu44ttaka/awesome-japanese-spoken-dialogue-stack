# TTS：ローカル実行の速度・メモリ・読みの正確さ（2026-08-19）

- 環境：[benchmarks/README.md](../README.md) の 2026-08 の PC
- RTF は「生成時間 ÷ 音声の長さ」。小さいほど速い。「x実時間」は音声の長さの何倍速で作れたか
- 長文は約 90 文字の共通の文
- ASR 検査は、合成した音声を Qwen3-ASR 0.6B（ONNX）で書き起こした CER。欠落・繰り返し・読み間違いの検出用で、声の自然さの評価ではない

| モデル | 実行のしかた | 長文 RTF / x実時間 | メモリ | ASR 検査 | 判定 |
|---|---|---:|---:|---|---|
| AivisSpeech | 独立エンジン + HTTP API・GPU | **0.054 / 18.5x** | RAM 941 MB | 短文は完全一致、長文 CER 0.069 | **総合 1 位**。日本語向けで導入が楽 |
| Irodori-TTS v4.1 Small | PyTorch BF16・40 steps | **0.092 / 10.9x** | GPU 3.56 GB、RAM 4.48 GB | 短文は完全一致、長文 CER 0.035 | **品質・機能 1 位**。声の設計・クローン |
| Tsukasa Speech | PyTorch・5 steps | **0.015 / 66.0x**（2 回目以降） | GPU 3.11 GB、RAM 5.02 GB | 短文は完全一致、長文 CER 0.069 | とても速い・アニメ調。非商用、導入が難しい |

## 補足

- Tsukasa の 1 回目はカーネルの初期化込みで RTF 0.241。2 回目以降は約 0.015。
- Supertonic は品質優先の 12 steps。8 steps なら長文 RTF 0.697（完全に CPU）。
- mio-tts-cpp は測定ごとにプロセスを起動し直しているので、値にモデルのロードが含まれる。既定の最大 400 トークンでは長文の末尾が切れたため、800 にして測った。
- Kokoro は長文が 510 音素の上限を超え、句読点での分割も必要だった。日本語の音素化（G2P）の出力が崩れていて、速さを比べる意味がない。
- 数字を含む文の CER は「八月」と「8月」のような表記の違いでも増えるので、順位には使っていない。

## Python なしで動かせるか

| モデル | Python なしで推論できるか |
|---|---|
| AivisSpeech | **できる**。エンジンの実行ファイル + HTTP API |
| mio-tts-cpp | **できる**。C++17 / GGML、CLI / HTTP サーバー |
| Supertonic3 | **できる**。ONNX で C++、C#、Go、Rust、Java、Node、Swift などの公式例あり |
| Kokoro | できる（ONNX Runtime の各言語ラッパー）。ただし日本語には勧めない |
| Irodori / Qwen3-TTS / CosyVoice / Tsukasa / Fish | 公式の経路は主に Python。別プロセスにして HTTP で使うことはできる |

## 推奨

1. **AivisSpeech** — 日本語アプリ・会話・ローカル API。入れてすぐ安定して使いたいとき
2. **Irodori-TTS v4.1 Small** — 高品質・声の設計・クローン・MIT ライセンスを優先するとき
3. **mio-tts-cpp** — CPU・省メモリ・Python なし・組み込み。数字は前処理で正規化する
4. **Tsukasa Speech** — 非商用で、キャラクターの表現力を優先し、環境の保守を許容できるとき
5. **Supertonic3** — 多言語・多ランタイム・CPU 配布。開発終了のリスクを許容できるとき

最終的に選ぶ前に、同じ音声をヘッドホンで聴き比べてください（ASR 検査では声の質や自然さは分かりません）。
