## 音声対話での速さ（sherpa-onnx・CPU 8 スレッド）

音声対話に組み込んだ状態で、1 発話あたりの認識時間を測った。1 発話目（ウォームアップ）は除く。CER は句読点・数字の整形（ITN）を有効にした値。

| モデル | CER | 平均 ms | 最悪 ms | メモ |
|---|---:|---:|---:|---|
| Fun-ASR-Nano-2512 | **0.088** | 629 | 906 | 最も高精度。生成上限 128 トークン（既定 512 だと最悪 2473 ms） |
| SenseVoiceSmall | **0.090** | **86** | **123** | 精度と速さの両立 |
| Cohere ASR Japanese | 0.105 | 632 | 799 | |
| Parakeet TDT 0.6B Japanese（CTC 版） | 0.121 | 157 | 193 | CTC だけのエクスポートなので GGUF 版より低い |
| Qwen3-ASR 0.6B（ONNX） | 0.111 | 2146 | 9753 | |
| Nemotron Speech ASR 0.6B（ONNX） | 0.173〜0.192 | 約 400 | | 唯一の真のストリーミング |

### 分かったこと

- **配布されている int8 モデルは CPU のほうが速い。** dynamic 量子化で CUDA のカーネルが効かず、GPU だと遅いうえ最悪値が跳ねる（SenseVoiceSmall：CPU 86 ms / 最悪 123 ms、CUDA 107 ms / 最悪 2315 ms）。
- **ITN（句読点・数字の整形）は有効にする。** 正解文に句読点があるため CER が下がる（SenseVoiceSmall：0.153 → 0.090）。後段の LLM に渡す文としても読みやすい。
- **sherpa-onnx の SenseVoiceSmall は `...-int8-2024-07-17` を使う。** 同じ名前の `2025-09-09` は広東語向けの追加学習版で、日本語を簡体字で書き起こす（CER 0.79）。
- **疑似ストリーミングは精度が落ちる。** 720 ms ごとに区切って独立に認識すると、CER 0.153 → 0.290、処理時間は約 3.2 倍になった。発話区間検出（VAD）で区切って一括で認識するほうがよい。
