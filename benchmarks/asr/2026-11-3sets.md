# ASR：3 つの公開評価データでの比較（2026-11）

JSUT 20 発話（[2026-08](2026-08-jsut20.md)・[2026-11](2026-11-jsut20.md)）ではどのモデルも CER 0.02〜0.05 に収まり、95% 区間が重なって差が分からなかった。そこで、性質の違う 3 つの公開評価データで 21 構成を比べた（2026-11-16 に 5 モデルを加え、11-17 に設定の誤りを直して測り直した。[下](#測り直したもの2026-11-17)）。あわせて、[MaAI-SDS](https://github.com/kazu44ttaka/MaAI-SDS) で実際に使っている設定の 2 構成も測った（[下](#maai-sds-の設定)）。2 人の自由会話でも 29 構成を測った（[下](#会話magichub-の自由会話)）。

処理時間は、ここでは参考値（CPU と GPU が混ざっている）。**同じ 100 発話を GPU・CPU に分けて測った処理時間は [2026-11-timing.md](2026-11-timing.md)** にある。

## 指標：読みの CER

句読点や表記（「1 つ」と「一つ」、「行く」と「いく」）の違いは、音声対話では問題にならないことが多い。そこで正解文と認識結果を **カタカナの読みに変換してから** 比べた CER を主な指標にした（[scripts/scoring.py](scripts/scoring.py)：NFKC 正規化 → 空白と句読点を除く → fugashi + unidic-lite で読みに変換）。

値はすべて **全体の CER**（すべての発話の誤り文字数の合計 ÷ 正解の文字数の合計）。95% 区間は発話を選び直すブートストラップで求めた。

## 分かったこと

- **3 つともで上位なのは Haas-ja・Cohere ASR・Fun-ASR-MLT-Nano。** ただし Haas-ja は ReazonSpeech と Common Voice を学習に使っている（†）。学習に入っていない FLEURS だけで比べると、Fun-ASR-MLT-Nano（0.014）・Cohere（0.025）・Whisper large-v3-turbo（0.028）・Haas-ja（0.029）の順。
- **速さと精度を両立するなら Haas-ja（GPU 43 ms）と Granite TurboCTC（GPU 16 ms）。** CPU だけなら ReazonSpeech k2（62 ms）。音声対話で話し終わってから文字が出るまでの時間を短くしたいときの第一候補。
- **ReazonSpeech（放送の話し言葉）で差が大きく開く。** 読み上げの FLEURS・Common Voice ではほとんどのモデルが 0.03〜0.06 だが、ReazonSpeech では 0.04〜0.28 まで広がる。実際の対話に近いのはこちらなので、モデル選びではこの列を重く見るとよい。ただし ReazonSpeech の正解文はテレビの字幕から作られていて、話した言葉の一部が抜けていることがある。聞こえたとおりに全部書き起こすモデルほど不利になる。
- **Moonshine base-ja は ReazonSpeech で 2 位（0.045）。** 一方で 20 秒を超える長い発話では、最後に同じ言葉を繰り返すことがあり、FLEURS では 0.077 に下がる。
- **Whisper large-v3-turbo（transformers）は、繰り返しの暴走を止める指定を入れると faster-whisper 以上になる。** 圧縮率（トークン空間で 1.35）と平均の対数確率（-1.0）の基準を外れた出力は、温度を上げて出し直す。これで ReazonSpeech は 0.123 → 0.073 になった。faster-whisper（0.104）は既定で同じ仕組みを持つが、ここでは `beam_size=1`・`condition_on_previous_text=False` で使っている。出し直す発話がある分、平均の時間は少し延びる。
- **Voxtral Mini 4B Realtime は、日本語では中位以下で遅い。** ReazonSpeech で 1000 発話のうち 96 発話、FLEURS で 22 発話に何も出さなかった。言語を指定する入力が無い（mistral-common の書き起こしの経路は言語の指定を使わない）。transformers で 1 トークン約 44 ms かかり、公式が勧めるのは vLLM。まとめて認識（batch）すると 40 発話中 4 発話で結果が変わったので、1 発話ずつ測った。
- **Nemotron 3.5 streaming は、真のストリーミングと引き換えに精度が低い。** 特に、短い発話や話し言葉で **何も出さない** ことがある（ReazonSpeech の 1000 発話のうち NeMo 版 131・sherpa-onnx 版 125、Common Voice で 38・27）。NeMo 版と sherpa-onnx 版の両方で起き、言語の指定を外すとポルトガル語やフランス語のような出力になる発話もあったので、測り方ではなくモデルのふるまいと考えている。ただし、音声全体を一度に渡す使い方では確かめていない。
- **Qwen3-ASR 0.6B は、読み上げでは中位だが ReazonSpeech で崩れる（PyTorch 版 0.228・sherpa-onnx 版 0.245）。** 短い発話に長い別の文を出すことが多い。sherpa-onnx 版は認識のたびに `stream.set_option("language", "Japanese")` で言語を指定し、出力の頭の `language Japanese<asr_text>` を取り除く（MaAI-SDS と同じ）。指定しないと、ReazonSpeech で 27 発話が韓国語や英語で出た。
- **SenseVoiceSmall と sherpa-onnx 版の Fun-ASR-Nano は、ReazonSpeech で大きく崩れる。** 短い発話に対して、正解よりずっと長い別の文を出すことが多い。funasr（PyTorch）版の Fun-ASR-Nano は 0.132 で、sherpa-onnx 版（0.217）よりかなりよい。
- ReazonSpeech の正解が「あ。」の 1 発話は、SenseVoice・Qwen3-ASR（sherpa-onnx）・Voxtral が同じ英語の文を出した。音声が実際には英語で、正解ラベルの誤りとみられる。

## 注意：学習データとの重なり

評価データと同じ（または同じ出どころの）音声で学習したモデルは、そのデータで有利になる。

| モデル | 重なり |
|---|---|
| Haas-ja v1.0 † | ReazonSpeech・Common Voice 26.0・YODAS で学習（モデルカード）。ReazonSpeech と Common Voice の値は有利に出ている。FLEURS は学習に入っていない |
| Granite 4.0 1B Speech † | Common Voice 17 の日本語を学習に使っている（モデルカード）。Common Voice の値は有利に出ている |
| ReazonSpeech k2-v2 †・Kotoba-Whisper v2.0 † | ReazonSpeech コーパスで学習している。ReazonSpeech の値は有利に出ている |
| Fun-ASR-MLT-Nano | FLEURS だけ飛び抜けてよい（0.014）。FLEURS を学習に使っている可能性があるが、**確かめていない** |
| Granite Speech 5.0 TurboCTC | Common Voice だけ飛び抜けてよい（0.014）。Common Voice を学習に使っている可能性があるが、**確かめていない** |

そのため、1 つの評価データで 1 位かどうかより、**3 つを通して安定しているか** を見るほうがよい。

## MaAI-SDS の設定

[MaAI-SDS](https://github.com/kazu44ttaka/MaAI-SDS) で実際に使っている設定（`controller_config.json` と `asr/engines_local.py`）でも測った。表の「MaAI-SDS の設定」の 2 行。

| 構成 | このページのほかの行との違い | 結果 |
|---|---|---|
| ReazonSpeech k2-v2（`sherpa-reazonspeech-k2-sds`） | 認識の前に先頭へ 0.5 秒の無音を足す（MaAI-SDS は zipformer の先頭を安定させるために足している） | **無音を足すと悪くなった**（0.068 / 0.055 / 0.024 → 0.077 / 0.078 / 0.027）。速さはほぼ同じ（CPU 94 → 96 ms） |
| Kotoba-Whisper v2.2（`faster-whisper-sds`） | `RoachLin/kotoba-whisper-v2.2-faster` を int8_float16・beam 5 で動かし、先頭へ 0.5 秒の無音を足す（MaAI-SDS は `asr_whisper_hf` を優先するので、こちらが使われる） | 0.043 / 0.112 / 0.040。Kotoba-Whisper v2.0（transformers）の 0.041 / 0.078 / 0.040 より ReazonSpeech で悪い。GPU で 1 発話 176 ms |

- どちらも 1 回の測定で、どの設定が効いたかは切り分けていない（無音・beam・量子化を 1 つずつ変えては測っていない）
- このページの 3 つの評価データでは、ReazonSpeech k2 に先頭の無音を足す利点は見えなかった。これらの音声は、話し始めの前に無音が残るように切り出されているため
- **音声がいきなり始まる区間では、先頭の無音が大きく効く**（2026-11-21）。
  - 会話のデータを書き起こしの時刻どおりにぴったり切り出したとき、ReazonSpeech k2 の読みの CER は、無音なし 0.227・先頭に 0.5 秒 0.148
  - デモアプリ（MaAI-SDS と同じしくみ）の疑似ストリーミングで JSUT を認識したとき、プリロール 0.5 秒にそろえても、無音なし 0.022・先頭に 0.5 秒 0.010
  - アプリと MaAI-SDS の既定のプリロール 0.2 秒では、VAD が始まりと判定するのが話し始めの 0.15 秒ほどあとなので、区間の頭に残る無音は 50 ms ほどしかない。このとき ReazonSpeech k2 は最初の語を落とした（「水をマレーシアから…」→「マレーシアから…」）
  - MaAI-SDS が ReazonSpeech k2 にだけ先頭の無音を足しているのは、この落ち方を防いでいることになる。ほかのモデルの区間の頭への強さは、[会話](#会話magichub-の自由会話) と [ストリーミング](../2026-11-runtimes.md#ストリーミング) の結果を参照

## 会話（MagicHub の自由会話）

3 つの評価データはどれも読み上げか放送で、音声対話の相手の話し方（相づち・言いよどみ・くだけた言い方）とは違う。そこで、2 人の自由会話で 29 構成を測った（2026-11-21）。

| 評価データ | 内容 | 使った区間 | 平均の長さ | ライセンス |
|---|---|---:|---:|---|
| [MagicHub Japanese Spontaneous Conversation](https://huggingface.co/datasets/MagicHub/Japanese_Spontaneous_Conversation_Training_Dataset) | 2 人の自由会話を話者ごとに iPhone で録音 | 1000（乱数で選択） | 3.0 秒（前後の無音を除く） | 再配布できない（評価にだけ使う） |

- 書き起こしの区切りで切り出し、長さ 0.5〜20 秒から seed 0 で 1000 区間を選んだ。聞き取れない・重なり・別の人の声などの印がある区間と、録音の始めの決まり文句は除いた
- 区間の前後に 0.5 秒の無音を足した。書き起こしの時刻どおりに切ると音声がいきなり始まり、頭を落とすモデル（ReazonSpeech k2 など）が大きく不利になるため（[上](#maai-sds-の設定)）
- 作り方は [scripts/make_extra_sets.py](scripts/make_extra_sets.py)。音声も書き起こしもこのリポジトリには入れていない
- 時間は GPU（sherpa-onnx の行も CUDA）。ほかの 3 つの列の時間とは条件が違うので、比べるのは同じ列の中だけにする

### 分かったこと（会話）

- **会話では、読み上げで上位のモデルの順位が入れ替わる。** いちばんよいのは speech.cpp の Qwen3-ASR 1.7B（0.092）と Fun-ASR-MLT-Nano（0.099）で、Qwen3-ASR 0.6B（0.105）が続く。Qwen3-ASR は ReazonSpeech では崩れた（0.196〜0.228）が、会話では上位になる
- Haas-ja（0.134）・Parakeet TDT-CTC（0.129）・Cohere（0.133〜0.146）・ReazonSpeech k2（0.147）は 0.13〜0.15 にまとまり、速さを考えると Haas-ja・Parakeet が引き続き有力
- **前後の無音の有無で値が大きく変わるモデルがある。** 無音なしから 0.5 秒ずつ足すと、ReazonSpeech k2 は 0.227 → 0.147、ReazonSpeech NeMo v2 は 0.242 → 0.166、Moonshine tiny-ja は 0.249 → 0.180 とよくなった。反対に SenseVoiceSmall は 0.101 → 0.132、Fun-ASR-MLT-Nano は 0.082 → 0.099、Cohere（CrispASR・audio.cpp）は 0.12〜0.13 → 0.13〜0.14 と少し悪くなった。区間の切り方しだいで順位が動くので、会話の値は 0.01〜0.02 の差を気にしないほうがよい
- **Fun-ASR-Nano は、無音を足した区間で繰り返しが暴走することがある。** 1000 区間のうち 3 区間（正解はどれも数文字の相づち）で同じ文字を 500 字ほど出し続け、全体の CER が 0.176 になった（95% 区間も 0.093〜0.275 と広い）。この 3 区間を除くと 0.093
- **Nemotron と Voxtral は、短い相づちに何も出さないことが多い。** 1000 区間のうち Nemotron（sherpa-onnx 560 ms）367・Voxtral（CrispASR）277 で何も出なかった
- anime-whisper（アニメ・ゲームの台詞で追加学習した Kotoba-Whisper v2.0）は 0.148 で、Whisper large-v3-turbo（0.152）・Kotoba-Whisper（0.158）と同じくらい。CrispASR の GGML 版（q8_0）は 0.269 と大きく悪い
