# ASR：同じ 100 発話での処理時間（GPU と CPU、2026-11）

[3 つの評価データでの比較](2026-11-3sets.md) は、モデルごとに CPU と GPU が混ざっていて、処理時間を比べられなかった。そこで **同じ 100 発話** を、**GPU だけ** と **CPU（8 スレッド）だけ** の 2 通りで測り直した。

- 評価セット：[scripts/make_timing_set.py](scripts/make_timing_set.py) で作る `timing100`。ReazonSpeech 40・Common Voice 30・FLEURS 30 発話（seed 1）。平均 8.5 秒、1.1〜24 秒
- 測り方：[scripts/eval_asr.py](scripts/eval_asr.py) `--manifest data/eval/timing100/manifest.json --warmup 3`。最初の 3 発話でウォームアップしてから 100 発話を 1 つずつ認識し、認識し終えるまでの時間を測った
- CPU：`--threads 8`（torch / ONNX Runtime / CTranslate2 のスレッド数。`OMP_NUM_THREADS=8`）。この CPU（Core Ultra 9 275HX）は 24 コアのうち 16 コアが省電力用の E コアで、スレッドを増やすとかえって遅くなることがある
- 条件：AC 電源・Windows の電源プラン「高パフォーマンス」・Legion のパフォーマンスモード。ほかの重い処理は止めた。各段階の前後で電源・空きメモリ・CPU を使っているプロセス・GPU の状態を記録した
- 測定日：2026-11-16〜17。1 回だけの測定なので、数 % の差は気にしない。sherpa-onnx の Qwen3-ASR（言語の指定を直したもの）と
  「MaAI-SDS の設定」の 2 行は 11-17 の昼に測った（同じ電源・電源プラン・パフォーマンスモード）
- 読みの CER はこの 100 発話でのもの（参考）。精度の比較は [3 つの評価データ](2026-11-3sets.md) を見る

- **sherpa-onnx は、GPU では fp32 の配布物を使った。** int8 は一部の演算（MatMulInteger など）が CUDA に載らず CPU に戻るので、GPU で動かすと CPU より遅くなる（最初の測定では SenseVoice 110 ms・ReazonSpeech k2 145 ms・Fun-ASR-Nano 1322 ms。fp32 で 41・72・902 ms）。fp32 の配布が無い Cohere・Parakeet TDT-CTC・Qwen3-ASR・Nemotron の sherpa-onnx 版は、GPU の表に入れていない
- Fun-ASR-Nano（sherpa-onnx）は fp32 でも CPU の int8（851 ms）より遅い
- 「MaAI-SDS の設定」の行は [MaAI-SDS](https://github.com/kazu44ttaka/MaAI-SDS) で実際に使っている設定。精度は [3 つの評価データのページ](2026-11-3sets.md#maai-sds-の設定) にある
- **Voxtral・Qwen3-ASR・Granite 4.0 1B は、transformers で 1 トークンずつ生成しているので遅い。** 公式は vLLM を勧めている（Voxtral は 1 トークン約 44 ms、GPU の使用率 59%）。vLLM での値は測っていない
- Whisper large-v3-turbo（transformers）の最大 3.1 秒は、繰り返しの暴走を止めるために温度を上げて出し直した発話

- Haas-ja と Voxtral は GPU だけで動かす前提なので測っていない。Parakeet CTC 1.1B ja は CPU で約 9 GB のメモリを使い、測定が止まったので外した
- **Granite TurboCTC は、CPU では float32 にする。** transformers 5 は既定でモデルの設定どおりの型（このモデルは bfloat16）で読み込み、CPU の bfloat16 はとても遅い（最初の測定では 6118 ms。float32 で 316 ms）
- Whisper large-v3-turbo（transformers）の最大 34.9 秒も、出し直しの分。CPU で Whisper を使うなら faster-whisper（int8）のほうが速い

## 分かったこと

- **GPU があるなら Granite TurboCTC（16 ms）と Haas-ja（42 ms）が飛び抜けて速い。** どちらも精度も上位。
- **CPU だけなら sherpa-onnx の SenseVoice（89 ms）・ReazonSpeech k2（94 ms）・Parakeet TDT-CTC（180 ms）。** 精度を重く見るなら ReazonSpeech k2 か Parakeet TDT-CTC。Cohere（780 ms）は精度は最上位だが、1 発話に 1 秒前後かかる。
- **LLM 型（エンコーダ + 言語モデルのデコーダ）のモデルは、GPU でも 0.6〜1.2 秒かかる**（Fun-ASR・Qwen3-ASR・Granite 4.0 1B）。話し終わってからの待ち時間が効く音声対話では、CTC やトランスデューサ（Granite TurboCTC・ReazonSpeech k2・Parakeet）や Haas-ja のほうが向いている。
